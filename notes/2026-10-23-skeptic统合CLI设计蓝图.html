              skeptic 统合 CLI 设计蓝图

              把 RTL 回归 debug 管线做成多子命令 CLI（flatten / static / build / dynamic / debug / diagnose）
              来源：wave-session · wave-mcp --session · flatten_fl.py · 信息截至 2026-10-23

              1背景：四阶段 debug 管线 背景

              先看清每天实际在做的四段重复劳动，才知道 CLI 该长什么样

              回归 debug 的日常是一条固定流水线，串起设计工程师、验证工程师和 AI 三方：

              阶段谁做产出
              ① DUT 更新设计工程师新一版 RTL
              ② 静态 session 更新验证工程师版本化静态 session（纯结构，无波形）
              ③ 回归用例回归工具一批 case 目录，fail 的每个都有 fsdb
              ④ fail case debug验证工程师 + AI逐 case 建动态 session，进各自目录调 agent
              这一步一步全是手工敲

              每个环节都要手动拼 wave-session 命令、手动写 .mcp.json、手动 claude 起会话；尤其第 ④ 段，fail 一个就要重复一遍。CLI 的目标是把「静态 session 只建一次、动态 session 复用结构、每个 case 一键进 debug」这三件事固化下来。

              静态 session 要作为副本保留、随 DUT 版本化（每次 DUT 更新重建一份，历史不覆盖），这样任意 fail case 都能回指到对应版本的结构基线。这是整套设计的锚点。

              2命令总览：六个子命令 总览

              主命令 skeptic，Python 3 + argparse subparsers，无第三方依赖，离线可用

              跑在内网登录机，内部 bsub -q centos8 -Is 'unset PYTHONPATH; …' 派发到计算节点。六个子命令一条依赖链：

              skeptic
├── flatten     套壳：调同目录 flatten_fl.py
├── static      扁平 filelist + top → 版本化静态 session
├── build       = flatten + static
├── dynamic     单 case 产动态 session（时序增量）
├── debug       单 case 产 .mcp.json（预置 --session）+ 启动 claude
└── diagnose    = dynamic + debug
              命令做什么输入输出
              flatten套壳 flatten_fl.py多个非扁平 filelist一个扁平 .f
              static版本化静态 session扁平 .f + topsession.json + netlist/maps.json
              buildflatten + static 二合一非扁平 .f + topflat.f + 静态 session
              dynamic单 case 动态 session（时序增量）case 波形 + 静态 sessioncase/session
              debug产 .mcp.json + 起 claudecase 目录.mcp.json
              diagnosedynamic + debug 二合一case + 静态 session直接进 claude
              日常只碰两条

              DUT 更新后跑一次 build 准备结构；每个 fail case 跑一次 diagnose 直达 claude。

              # DUT 更新后，准备结构（跑一次）
skeptic build --filelist xxx.f --top top_tb --static-root /path/static --dut-version 1.2.3

# 每个 fail case，一键进 claude debug
skeptic diagnose --case /abs/path/case01 --static-session /path/static/1.2.3 --filelist /path/static/1.2.3/flat.f --top top_tb

              3各命令详细规格 规格

              签名 + 伪代码 + 一个关键点；按依赖链从上到下排

              flatten · 套壳

              skeptic flatten -o <out.f> <filelist1> [filelist2 ...]

              参数与 flatten_fl.py 保持一致：-o 输出 + 位置参数多个输入。

              def cmd_flatten(args):
    script = os.path.join(os.path.dirname(__file__), "flatten_fl.py")
    subprocess.run(["python3", script, "-o", args.out] + args.filelists, check=True)

              关键点：flatten_fl.py 与本脚本同目录，用 __file__ 定位；check=True 让 flatten 失败时 skeptic 一并报错退出。

              static · 版本化静态 session

              skeptic static --filelist <扁平.f> --top <top> --static-root <dir> --dut-version <ver>
              out = f"{args.static_root}/{args.dut_version}"
bsub(f"wave-session --static --filelist {args.filelist} --top {args.top} --out {out}")

              产物：<static-root>/<dut-version>/session.json + netlist/maps.json，历史全留（版本化，不覆盖）。

              build · = flatten + static

              skeptic build --filelist <非扁平.f> [更多...] --top <top> --static-root <dir> --dut-version <ver>
              flat = f"{args.static_root}/{args.dut_version}/flat.f"   # 扁平产物跟静态 session 放一起，保留
flatten(flat, args.filelists)                            # flatten_fl.py -o flat.f xxx.f ...
static(filelist=flat, top=args.top, out=f"{args.static_root}/{args.dut_version}")

              关键点：flat.f 落在静态 session 目录内，后续 dynamic/diagnose 直接引用它，不用重跑 flatten。

              dynamic · 单 case，时序增量

              skeptic dynamic --case <case绝对路径> --static-session <静态session目录绝对路径> --filelist <flat.f> --top <top>
              wave = find_waveform(args.case)                 # 优先 *.fsdb，否则 *.fst；都无则报错
out  = f"{args.case}/session"
bsub(f"wave-session --vcd {wave} --filelist {args.filelist} "
     f"--top {args.top} --out {out} --no-netlist")       # --no-netlist 跳过重复解析 RTL
rewrite_maps(f"{out}/session.json", f"{args.static_session}/netlist/maps.json")
              def rewrite_maps(session_json, static_maps):
    m = json.load(open(session_json))
    m["maps_path"] = static_maps                 # null → 静态 maps.json 绝对路径
    json.dump(m, open(session_json, "w"), indent=2)

              关键点：结构复用静态（maps 指回静态），只增量加时序（波形 fst）。

              debug · 单 case，预置 session

              skeptic debug --case <case绝对路径>
              session = f"{args.case}/session"
mcp = {"mcpServers": {"wave-mcp": {
    "command": "bash",
    "args": ["-c",
        f"bsub -q centos8 -Is 'unset PYTHONPATH; "
        f"<部署目录>/runtime/bin/wave-mcp --session {session}' "
        f"| grep --line-buffered '^{{'"]}}}
json.dump(mcp, open(f"{args.case}/.mcp.json", "w"), indent=2)
os.chdir(args.case)
os.execvp("claude", ["claude"])                  # 接管终端，开始对话

              关键点：.mcp.json 里 wave-mcp 带 --session（官方语义 auto-open at startup），claude 一启动 session 就绪，用户直接问波形。

              diagnose · = dynamic + debug

              skeptic diagnose --case <case绝对路径> --static-session <静态session目录> --filelist <flat.f> --top <top>

              内部先跑 dynamic 逻辑，再跑 debug 逻辑，一条命令从 case 波形直达进 claude。

              4三个关键机制 机制

              三个机制是整套设计的骨架，缺一个就退回手工

              机制作用落在哪条命令
              复用 netlist静态建 1 次结构，所有动态 session 共用 maps.json，避免每 case 重解析 RTLdynamic 的 --no-netlist + 改 maps_path
              --session 预置生成的 .mcp.json 给 wave-mcp 传 --session，省掉手动 open_sessiondebug / diagnose
              bsub 派发 + 横幅过滤所有 wave-session/wave-mcp 都套 bsub；MCP 侧加 grep 滤掉 Job <id> is submitted 横幅全部命令
              为什么先复用 netlist，再谈并行

              并行只是把「每个 case 各建一次」同时做，省的是墙钟时间；而 netlist 复用省的是每 case 重复解析 RTL 的算力，这是更大的浪费。所以先固化结构复用，多 case 并行放到最后再定。

              5目录结构 结构

              静态与动态分家：静态侧版本化快照，动态侧逐 case 自洽

              static-root/
  <dut-version>/
    flat.f              # build 时 flatten 产物，保留供 dynamic 复用
    session.json
    netlist/maps.json   # 唯一结构基线

cases-root/
  case01/
    case01.fsdb         # 波形名不固定，自动发现
    session/            # dynamic 生成
      session.json      #   fst_path=转出fst, maps_path→静态 maps.json
    .mcp.json           # debug 生成（预置 --session）

              静态侧每次 DUT 更新加一个 <dut-version> 目录，历史只增不减；动态侧每个 case 目录自包含（波形 + 自己的 session + 自己的 .mcp.json），互不干扰。

              6落地顺序与待定 待定

              按依赖先易后难推进，两个风险点先小范围验证

              落地顺序

              1. flatten（套壳，独立，被 static/build 依赖）
              2. static + build
              3. dynamic（先验证「maps 跨目录复用」风险点）
              4. debug（验证 --session 预置）
              5. diagnose 合成
              6. 多 case 并行——后续再定

              待定项

              • 脚本载体 / 拓扑：Python + 登录机 bsub 派发为建议，实现时可改 bash/csh 或放计算节点
              • 多 case 并行机制：先跑通单 case，并行另议
              • 两个待验证风险点：maps 跨目录复用、--session 预置（都在落地顺序 3/4 里先验证）
