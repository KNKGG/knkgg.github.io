                                                    波形 Debug 工具 · wave-mcp 与 fsdb-mcp 使用指南

                                                    两个让 AI Agent 直接读波形、查信号、追根因的 MCP Server：一个走开源 FST 路线，一个借 Verdi NPI 读 FSDB
                                                    来源：github.com/Tencent/wave-mcp（Apache-2.0，37 工具）· github.com/hjxxlogic/fsdb-mcp（10 工具，依赖 Verdi）· 信息截至 2026-09

                                                    1先搞懂底座：MCP 是什么 概念

                                                    前面所有工具都叫「MCP Server」，先把 MCP 这个底座讲清楚，后面就全串起来了

                                                    1.1 一句话本质

                                                    MCP = Model Context Protocol（模型上下文协议），是 Anthropic 于 2024 年底提出、后来开放给全行业的一个标准，规定「AI 应用」和「外部工具/数据」之间怎么通信。它不是某个软件，而是一份接口规范。

                                                    1.2 解决什么问题：M×N → M+N

                                                    没有 MCP 之前，AI 想调用外部工具（读波形、查数据库、访问 GitHub、操作文件），每对「AI × 工具」都要单独写一段对接代码——M 个 AI 应用 × N 个工具 = M×N 份胶水代码。有了 MCP，双方只认这一套标准：工具方实现一次，任何 AI 方都能用。M×N 变成 M+N。这跟做验证用 UVM 是同一个动机。

                                                    1.3 用验证工程师熟悉的东西类比

                                                    MCP Server 之于 AI，就像 UVC 之于验证平台。

                                                    验证领域AI 领域
                                                    UVM 标准（定义 agent/driver/monitor 接口）MCP 标准（定义 tool 的接口）
                                                    第三方 UVC（符合 UVM 标准，即插即用）MCP Server（如 wave-mcp，符合 MCP 标准）
                                                    你的 testbench（UVM 环境，消费 UVC）AI 客户端（Claude Code 等，消费 MCP Server）
                                                    uvm_driver 通过 vif 驱动信号AI 通过 tool 调用「读信号值」这个能力

                                                    所以 wave-mcp / fsdb-mcp 本质上就是：有人把「读波形」这件事，按 MCP 标准封装成了 37 个 / 10 个工具函数，Claude Code 拿来就能调——就像你拿一个写好的 i2c_agent 插进平台直接用，不用自己从零写时序。

                                                    1.4 三个核心角色

                                                    • Client（客户端）：AI 应用，负责「决定要调哪个工具」。Claude Code、Cursor、Codex 都是。
                                                    • Server（服务端）：能力提供方，负责「真正执行」。wave-mcp、fsdb-mcp、读 GitHub/数据库的那些都是。
                                                    • Tool（工具）：最小调用单元——有名字、有参数、有返回值，本质就是一个「可被 AI 远程调用的函数」。

                                                    通信走 JSON-RPC（JSON 格式的远程过程调用），传输方式就是后文出现的 stdio（子进程标准输入输出）或 HTTP。

                                                    1.5 最小例子：AI 怎么调用工具

                                                    {
  "mcpServers": {
    "wave-mcp": {
      "command": "python",
      "args": ["-m", "wave_mcp.server", "--session", "sessions/my_module"]
    }
  }
}
                                                    ① 你在配置里告诉 AI：「有这个工具服务，用这条命令拉起它」
                                                    就是上面那段 mcpServers JSON
                                                    ② AI 启动时按配置拉起 server 子进程
                                                    stdio 方式，一人一进程
                                                    ③ server 汇报：「我有 37 个工具，比如 signal_values(paths, ...)」
                                                    ④ AI 需要查波形时，发 JSON-RPC 请求调用 signal_values
                                                    传参 paths="top.u_tx.tx_serial"
                                                    ⑤ server 真正去读 FST，把值算出来返回给 AI
                                                    ⑥ AI 拿到结果，接着推理
                                                    「这个信号在 85000ps 变了，说明……」
                                                    关键点

                                                    AI 自己并不知道怎么读 FST 文件，它只是「喊了函数名 + 传参数」，真正的读文件动作是 server 干的。MCP 把「AI 会推理」和「工具会干活」这两件事解耦了。

                                                    2总览：两个工具一句话

                                                    先搞清楚各自是什么、解决什么问题，再看细节

                                                    2.1 定位

                                                    两者都是 MCP（Model Context Protocol）Server：把「读波形、查信号」这件事包装成一组标准化的工具，让 Claude Code 这类 AI Agent 能像调用函数一样去查波形、追 X 态、定位 bug。区别在于波形数据源和要不要商用 License。

                                                    • wave-mcp（腾讯蓬莱实验室）：读 FST 波形 + RTL 网表，纯开源技术栈（pylibfst + pyslang），Apache-2.0 免 License。能力最强：层次探索、信号查询、驱动分析、值/X 态追踪、波形对比、浏览器波形查看器，共 37 个工具。
                                                    • fsdb-mcp（社区项目）：读 FSDB 波形，底层是 Synopsys Verdi 的 NPI（Native Programming Interface） 库，需要 Verdi + license。功能聚焦在「打开 FSDB → 浏览层次 → 查信号 → 取波形值」这一条基础链路，共 10 个工具。
                                                    类比：两种读盘方式

                                                    wave-mcp 像自己造了台开源读盘器，读的是 FST 这种开放格式，还能额外读懂 RTL 源码里的连接关系——不花钱、随便并发。

                                                    fsdb-mcp 像租用 Verdi 的官方读盘器，读的是 FSDB 这种闭源格式，读得又全又准，但要用 Verdi 的 license 开门。

                                                    2.2 快速选型表

                                                    你的情况推荐理由
                                                    手里是 FST / VCD 波形，或没有 Verdi licensewave-mcp免 License，FST/VCD 开箱即用，能力全
                                                    只有 FSDB，且机器装了 Verdi + license两者都行wave-mcp 能把 FSDB 转 FST 再读（转换不占 license）；fsdb-mcp 直接读
                                                    要追 X 态根因、做驱动/扇入分析、pass/fail 波形对比wave-mcp这些是 wave-mcp 的强项，fsdb-mcp 没有
                                                    只要基础读波形（查信号值/变化），环境里已有 Verdifsdb-mcp轻量、直接，工具少好上手

                                                    3wave-mcp：开源免 License 的波形调试 Apache-2.0

                                                    腾讯蓬莱实验室验证团队出品，37 个工具 / 12 大类，纯开源技术栈

                                                    3.1 它是什么

                                                    一个 RTL 波形调试 MCP Server，读 FST 波形 + RTL 网表，给 LLM 提供波形调试工具集。核心卖点：免 License、数据准确、真实芯片项目背书。

                                                    • FST 直读，VCD / FSDB 自动转 FST（prepare_session 一步完成，FSDB 转换不占 Verdi license）。
                                                    • 不跑仿真器：你用自己的流程跑出波形，把结果交给它即可。
                                                    • 静态分析：用 pyslang 把 RTL 完整精化成一张网表，仿真前就能查连接、驱动、扇入扇出。
                                                    • 生产级验证：真实芯片项目 + OpenTitan 27 个 IP + 香山 38 个 IP，225 万信号级值查询正确率 100%。
                                                    两个技术栈各管一半

                                                    pylibfst 负责读 FST 波形（随机访问、快）；pyslang 负责把 RTL 源码建成网表（提供连接、驱动、扇入扇出这类波形里没有的静态关系）。两者拼起来，才既能查「信号这一拍是什么值」，又能答「这值是被谁驱动的」。

                                                    3.2 系统要求

                                                    依赖要求说明
                                                    Python3.10 – 3.13已测 3.10–3.13 全通过；MCP SDK 要求 ≥ 3.10
                                                    glibc≥ 2.28pyslang 预编译 wheel 的要求（Ubuntu 18.10+ / Debian 10+ / CentOS 8+）
                                                    mcp2.x（≥2.0.0,<3）pip install 自动装
                                                    pylibfst≥ 0.2.1FST 波形读取（fstapi）
                                                    pyslang≥ 11.0.0RTL 网表构建（完整 elaboration）
                                                    vcd2fst（可选）GTKWave 附带仅 VCD→FST 转换需要

                                                    Linux x86_64 开箱即用。其他平台只有 pylibfst 需要源码编译（cmake + gcc + zlib），波形查看器暂不支持。

                                                    3.3 安装与快速开始

                                                    # 安装
pip install wave-mcp

# 一条命令：波形(.fst/.vcd) + filelist → session（自动转 FST + 建网表）
wave-session --fst sim/dump.fst --top top_tb --filelist rtl.f

# 启动 MCP Server（stdio，推荐：一人一进程）
python -m wave_mcp.server --session sessions/my_module

                                                    仓库还带了三个示例，方便跑通流程（examples/ 目录）：

                                                    • 示例 A Verilator 快启：counter 设计产出真实 FST，跑通 prepare_session 全流程（需 verilator≥5）。
                                                    • 示例 B 静态分析：UART 设计，无波形、无仿真器，展示仿真前分析。
                                                    • 示例 C 极小样例：手写 VCD → vcd2fst → FST，零依赖。

                                                    3.4 CLI 模式

                                                    不挂 Code Agent 也能在终端直接调全部 37 个工具（与 MCP 同名同参数）：

                                                    # 列出全部 37 个工具
wave-mcp query --list

# 查询信号值变化
wave-mcp query signal_values --session sessions/my_module \
    --paths top.u_tx.tx_serial

# JSON 传参
wave-mcp query signal_drivers --session sessions/my_module \
    --json-args '{"paths": "top.u_tx.tx_serial"}'

                                                    参数按工具签名自动生成，wave-mcp query <工具名> --help 查看。默认输出人读文本，加 --json 输出完整结构化结果。适合 CI 脚本、开发调试、快速验证。

                                                    3.5 接入 Code Agent

                                                    prepare_session 是 MCP 统一入口：Agent 想分析波形时第一步调它，传入波形，一次完成「（转换 →）建网表 → 建 session → 打开」。

                                                    prepare_session({
  "wave_path":     "sim/dump.fst",   // .fst 直读 / .vcd 自动转 / .fsdb 自动转
  "top":           "top_tb",
  "filelist_path": "rtl.f",          // 与仿真同一份 filelist
  "pack":          "fastlz"          // 转换压缩：fastlz/lz4/zlib，可省
})

                                                    各家 Agent 的 MCP 配置（Claude Code 写入 .mcp.json，或 claude mcp add）：

                                                    {
  "mcpServers": {
    "wave-mcp": {
      "command": "python",
      "args": ["-m", "wave_mcp.server", "--session", "/abs/path/to/sessions/my_module"]
    }
  }
}

                                                    还有个独家能力 open_static_session：只凭 RTL 源码建网表打开 session，不需要波形、不跑仿真，仿真前就能查接口、驱动、扇入扇出、浏览层次、做 code review。之后仿真出波形，用同一份 RTL 调 prepare_session 升级即可，网表自动复用。

                                                    3.6 37 个工具 / 12 大类

                                                    工具按功能分成 12 类，下面列出类别和代表工具：

                                                    类别代表工具说明
                                                    波形准备prepare_session / open_static_session / convert_vcd_to_fst / convert_fsdb_to_fst波形入口 → session 一条龙
                                                    会话管理open_session / close_session / session_infosession_info 含网表健康度 + 覆盖率
                                                    查询默认值query_defaults_set/get/clear按会话设默认信号与时间窗
                                                    层次探索find_instances / list_modules / scope_info模块名三层解析
                                                    信号查询list_signals / signal_info位宽/方向/类型/声明位置
                                                    值查询signal_values / signal_activity / find_time_windows / sample_at_clockFST 强项，随机访问；sample_at_clock 给逐拍表
                                                    时序与事务fold_transactions / fsm_transitions事务定义由调用方给
                                                    驱动分析signal_connectivity / signal_drivers / signal_loads / signal_fanin / signal_downstream / active_drivers / driver_contributorspyslang 网表（静态精确）+ 分支条件 4 值求值选活跃驱动
                                                    值 / X 态追踪trace_value / trace_x网表 × FST 值反向遍历，跨模块下钻
                                                    波形对比diff_waveformsN 份波形首分歧定位，按分歧时间排序信号
                                                    波形查看器open_wave_view / update_wave_view / get_view_state / list_wave_views / close_wave_view分析完自动弹浏览器波形，嫌疑信号 + 游标钉在出错时刻
                                                    文件filesfilelist + pyslang 网表
                                                    两个最值钱的工具

                                                    trace_x：追 X 态根因——沿驱动链反向遍历、跨模块下钻，每个节点带真实 FST 值，直接告诉你 X 是从哪个信号、哪条语句传进来的。diff_waveforms：对 pass/fail 两份波形定位首个分歧时刻，按分歧时间排序信号，配合 signal_fanin 做因果回溯。这是传统 Verdi 手动 debug 很难自动化做的事。

                                                    3.7 关键环境变量

                                                    多数人一个都不用配：装完读 FST/VCD、静态分析、波形查看器全开箱可用。只有两种情况需要配：

                                                    变量要配吗作用
                                                    VERDI_HOME读 .fsdb 时必配Verdi 安装根目录（不是 bin/），在其下找 share/FsdbReader/linux64
                                                    WAVE_MCP_TOKENHTTP 跨机时必配HTTP 传输的共享密钥（≥16 字符）
                                                    WAVE_MCP_SESSION_ROOT建议配session 落点根目录（HOME 有配额时指向本地大盘）
                                                    WAVE_MCP_CACHE_ROOT建议配派生缓存根目录
                                                    要配的话，写进 env，不要用 shell 的 export

                                                    Agent 以子进程方式拉起 Server，继承不到你交互式 shell 里的变量。要把 VERDI_HOME 这类变量写进 MCP 客户端配置的 env 块里才稳定生效：

                                                    {
  "mcpServers": {
    "wave-mcp": {
      "command": "wave-mcp",
      "env": {
        "VERDI_HOME": "/tools/synopsys/verdi/T-2022.06-SP1"
      }
    }
  }
}

                                                    3.8 部署模式

                                                    模式适用说明
                                                    stdio（推荐）每人本地一人一进程，零运维，不需配置
                                                    HTTP（本机）本机多客户端python -m wave_mcp.server --transport http --port 8000，绑回环地址不用配 token
                                                    HTTP（跨机器）别机连过来绑非回环地址必须设 WAVE_MCP_TOKEN，否则拒绝启动
                                                    离线自包含包隔离网有网机器 deploy/docker_build_all.sh 打 bundle，拷入后 install.sh 离线装

                                                    3.9 CentOS 7 / 老机器怎么办

                                                    官方 pyslang wheel 要求 glibc ≥ 2.28，CentOS 7（glibc 2.17）直接 pip install 装不上，会报 GLIBC_2.27 not found。解决办法：

                                                    • 用 glibc 2.17 档离线 bundle：deploy/docker_build_all.sh 自动在容器内自编兼容 wheel，产出 wave-mcp-bundle-glibc2.17.tar.gz，整条链路（独立 Python + wheel + vcd2fst + 静态 surver）在 glibc ≥ 2.17 均可运行，含 CentOS 7。
                                                    • 在容器里跑：如 python:3.11-slim，绕开平台差异，最省事。
                                                    • bundle 自带独立 Python 3.11，与系统 Python 无关，所以目标机 Python 是 3.8 / 3.9 也能用。

                                                    4fsdb-mcp：借 Verdi NPI 读 FSDB 需 license

                                                    社区项目 hjxxlogic/fsdb-mcp，10 个工具，底层是 Synopsys NPI

                                                    4.1 它是什么

                                                    一个读 FSDB（Fast Signal Database）波形的 MCP Server，通过 MCP 协议提供对 FSDB 文件的程序化访问，让 AI 助手能查波形数据、信号、scope、值变化。

                                                    底层走 Synopsys 的 NPI（Native Programming Interface）——Verdi 自带的 Python 绑定（pynpi），所以读的是 FSDB 这种闭源格式，读得又全又准，代价是要有 Verdi 环境和 license。

                                                    4.2 前置依赖

                                                    依赖要求
                                                    Python3.10+（MCP SDK 要求）
                                                    Synopsys Verdi带 NPI 支持
                                                    VERDI_HOME指向 Verdi 安装目录
                                                    pynpi随 Verdi 附带
                                                    Verdi license有效 license

                                                    4.3 安装

                                                    # 1. 设环境
export VERDI_HOME=/path/to/verdi
export LD_LIBRARY_PATH=$VERDI_HOME/share/NPI/lib/linux64:$VERDI_HOME/platform/linux64/bin:$LD_LIBRARY_PATH

# 2. 建并激活虚拟环境（Python 3.10+）
python3.10 -m venv venv
source venv/bin/activate

# 3. 装依赖
pip install --upgrade pip
pip install mcp

# 4. 测试安装
python test_fsdb.py

                                                    4.4 启动

                                                    python server.py

                                                    Server 通过 stdin/stdout 走 MCP 协议通信。接入 Code Agent 的配置与 wave-mcp 类似，把 command 指向 python server.py 所在路径即可。

                                                    4.5 10 个工具

                                                    工具全部以 fsdb_ 开头，命名直白，覆盖「打开 → 浏览 → 查信号 → 取波形值」这一条基础链路：

                                                    工具作用关键参数
                                                    fsdb_is_fsdb判断文件是不是有效 FSDBpath
                                                    fsdb_open打开 FSDB 文件path
                                                    fsdb_close关闭已打开的 FSDBpath
                                                    fsdb_get_info文件元信息（时间范围/版本/仿真日期等）path
                                                    fsdb_list_scopes列出层次中的 scopepath, scope_path
                                                    fsdb_list_signals列出某 scope 下的信号path, scope_path
                                                    fsdb_get_signal_info信号详细信息（类型/位宽/方向）path, signal_path
                                                    fsdb_get_signal_value某时刻的信号值path, signal_path, time, format
                                                    fsdb_get_signal_changes某时间范围内的值变化列表path, signal_path, start_time, end_time, format
                                                    fsdb_search按名称模式搜索信号/scopepath, pattern, search_type, scope_path

                                                    format 支持 bin / dec / hex / real 四种格式，默认 hex。大结果集会自动截断，防止内存问题（可配置）。

                                                    4.6 典型工作流

                                                    六步走完一次读波形：

                                                    ① fsdb_is_fsdb
                                                    确认文件是有效 FSDB
                                                    ② fsdb_open
                                                    打开波形文件
                                                    ③ fsdb_list_scopes
                                                    浏览层次
                                                    ④ fsdb_list_signals
                                                    列出 scope 下的信号
                                                    ⑤ fsdb_get_signal_changes
                                                    取某时间范围的值变化
                                                    用完收尾
                                                    ⑥ fsdb_close
                                                    关闭文件
                                                    // 1. 判断
{ "tool": "fsdb_is_fsdb", "arguments": { "path": "waveform.fsdb" } }
// 2. 打开
{ "tool": "fsdb_open", "arguments": { "path": "waveform.fsdb" } }
// 3. 列顶层 scope
{ "tool": "fsdb_list_scopes", "arguments": { "path": "waveform.fsdb" } }
// 4. 列某 scope 下的信号
{ "tool": "fsdb_list_signals", "arguments": { "path": "waveform.fsdb", "scope_path": "tb_top" } }
// 5. 取信号值变化

                                                    5对比与选型

                                                    把两个工具放在一起看，各适合什么场景

                                                    5.1 全面对比表

                                                    维度wave-mcpfsdb-mcp
                                                    出品方腾讯蓬莱实验室社区（hjxxlogic）
                                                    LicenseApache-2.0，免 License依赖 Verdi license
                                                    波形格式FST 直读；VCD / FSDB 自动转 FST仅 FSDB
                                                    技术栈pylibfst（读 FST）+ pyslang（RTL 网表）pynpi（Synopsys NPI）
                                                    工具数量37 个（12 大类）10 个
                                                    能力边界层次/信号/值 + 驱动分析 + X 追踪 + 波形对比 + 浏览器查看器 + 无波形静态分析打开/浏览/查信号/取波形值（基础读链路）
                                                    追 X 态根因有（trace_x）无
                                                    pass/fail 对比有（diff_waveforms）无
                                                    静态分析（仿真前）有（open_static_session）无
                                                    环境门槛Python 3.10–3.13 + glibc ≥ 2.28（老机器用 bundle）Python 3.10+ + Verdi + license
                                                    部署stdio / HTTP / 离线 bundle 三档stdio（python server.py）

                                                    5.2 什么时候选哪个

                                                    • 优先 wave-mcp，除非你被下面「选 fsdb-mcp」的条件卡住。它是开源路线，能力全、并发不限、不花 license 钱，还带 X 追踪和波形对比这种自动化 debug 的硬能力。
                                                    • 选 fsdb-mcp 的场景：环境里已有 Verdi + license、只想做基础的「打开 FSDB 查信号值」、不想折腾 FST 转换或网表；或者你的团队严格绑在 FSDB + Verdi 工作流上，读原始 FSDB 更省事。
                                                    • 两者不冲突：wave-mcp 也支持 FSDB（convert_fsdb_to_fst 自动转，转换不占 Verdi license），只是需要本机有 Verdi 的 FsdbReader 运行库。所以「只有 FSDB」不是非 fsdb-mcp 不可的理由。

                                                    5.3 结论

                                                    一句话结论

                                                    想认真让 AI 帮你 debug——追 X 态、找驱动、对比 pass/fail——选 wave-mcp，开源免 License 且能力碾压；只想在已有 Verdi 环境里轻量读一下 FSDB 波形，选 fsdb-mcp，简单直接。作为验证工程师，wave-mcp 的 trace_x 和 diff_waveforms 是传统手动 debug 很难自动化的两块，最值得先试。
