                    iPhone 连 Mac 终端跑 Claude Code

                    异地用手机连回 Mac 的完整方案：Tailscale 组网 + SSH + tmux + 合盖不睡，一套实测跑通的流程，附带踩过的坑
                    环境：macOS 14 Sonoma · Apple Silicon M3 Max · 目标：iPhone 上复用 Mac 完整的 claude code 环境 · 信息截至 2026-09

                    1方案架构 总览

                    核心就一句话：让 Mac 保持在线 + 可被异地连入，四个组件各管一段

                    Claude Code 是个终端程序（TUI），只要给它一个真终端就能跑。所以方案的本质是——把 Mac 上的终端「搬到」iPhone 上，同时保证 Mac 一直醒着、一直能连。

                    iPhone（Termius / 任意 SSH 客户端）
                    你真正敲命令的地方
                    Tailscale —— 异地组网
                    两端登录同一账号，无公网 IP 也能互通
                    SSH —— 远程登录
                    Mac 开「远程登录」，22 端口连进去
                    tmux —— 断线续命
                    常驻会话，手机断线了 claude 还在跑
                    claude code
                    Mac 上完整的环境（memory / skills 都在）
                    组件管什么没有它会怎样
                    Tailscale异地网络打通手机根本连不到 Mac
                    SSH 远程登录进 Mac 的终端连上了也没 shell 可用
                    tmux会话持久化断线一次 claude 就丢
                    disablesleep合盖不睡合盖就断，远程失效

                    2Tailscale：异地组网 组网

                    专治「两端都没有公网 IP、跨地域」的互通，不需要路由器开端口

                    Mac 和 iPhone 各装一个 Tailscale 客户端，登录同一个账号，就自动组成加密内网，iPhone 直接用内网 IP 连 Mac。

                    两端安装

                    • Mac：brew install --cask tailscale-app（注意 cask 名是 tailscale-app，不是 tailscale；装完在菜单栏点 Log in）
                    • iPhone：App Store 搜 Tailscale，登录同一个账号
                    两个易错点

                    ① cask 名带 -app 后缀；② .pkg 安装需要 sudo 密码，非交互终端装不了，要在自己的终端里跑。iPhone 端第一次打开会弹「添加 VPN 配置」，必须点允许。

                    装好登录后，Mac 会拿到一个 100.x.y.z 的动态 IP（菜单栏图标点开能看到）。这个 IP 是动态的，别记死，每次从菜单栏或 App 里看。

                    3SSH：远程登录 连入

                    这是 iPhone 连进来的硬前提，比 tmux 重要得多

                    在 Mac 上开启「远程登录」，iPhone 才能通过 SSH 拿到 Mac 的终端。

                    开启方式（二选一）

                    # 命令行
sudo systemsetup -setremotelogin on

# 或者 GUI：系统设置 → 通用 → 共享 → 打开「远程登录」

                    连接参数

                    参数值
                    地址Mac 的 Tailscale IP（100.x.y.z）
                    用户名wanghaodong（Mac 登录用户名）
                    端口22
                    密码Mac 登录密码
                    验证时的一个假象

                    macOS 的 sshd 是 on-demand（按需） 的：没连接时 22 端口由 launchd 持有，lsof 查不到监听是正常的；用 netstat -an | grep 22 或 nc -z 127.0.0.1 22 才能确认它真的在监听。连接进来时 launchd 会自动拉起 sshd。

                    4tmux：断线续命 持久

                    手机断线 = 会话还在 Mac 上跑，重连 attach 回来接着用

                    tmux 让 claude 会话和「SSH 连接」解耦：SSH 断了，会话不死。

                    核心命令

                    tmux new -s cc       # 起一个叫 cc 的常驻会话，进去敲 claude
tmux attach -t cc    # 断线重连后，重新进这个会话
tmux rename-session cc  # 给会话改名（裸 tmux 起的叫 0）
tmux ls              # 看有哪些会话

                    「离开」的两种方式，别搞混

                    你怎么做发生了什么claude 还在吗
                    手机断线 / 直接关 Termius自动 detach（分离）✅ 还在 Mac 上跑
                    Ctrl-b 然后 d手动 detach✅ 还在跑
                    会话里敲 exit（或 Ctrl-d）会话关闭（kill）❌ 被终止
                    一个类比

                    tmux 会话 = Mac 上一个「永远开着的终端标签页」。iPhone 的 SSH 只是你看它的窗口。手机断了 = 窗口关了，标签页还在跑 claude；重新 SSH + tmux attach = 重新打开窗口，接着用。

                    报「sessions should be nested with care」

                    这句话的意思是：你已经在一个 tmux 会话里了，又敲了 tmux 命令。忽略它，别再敲 tmux new / tmux attach，直接敲 claude 干活。

                    5合盖不睡 重点

                    这是整个方案最容易翻车的地方，也是踩坑最深的一环

                    5.1 核心坑：caffeinate 挡不住合盖

                    Apple Silicon MacBook 无外接显示器时，合盖走的是 Clamshell Sleep 这条独立代码路径。caffeinate（包括 -s 建立的 PreventSystemSleep 断言）压不住这条路径——实测插电合盖照样睡、照样断网。

                    结论

                    不要再用 caffeinate 声称能挡合盖。合盖睡眠是硬件/系统级的，和「空闲睡眠」是两回事。

                    5.2 正确做法：disablesleep

                    管 Clamshell Sleep 的是内核级 SleepDisabled 开关，用 disablesleep 翻转它：

                    sudo pmset -a disablesleep 1   # 合盖不睡
sudo pmset -a disablesleep 0   # 恢复（用完记得关！）

                    可以配成别名（写进 ~/.zshrc）：

                    alias cafe='sudo pmset -a disablesleep 1'     # 合盖不睡
alias cafeoff='sudo pmset -a disablesleep 0'  # 恢复

                    5.3 三个副作用，得知道

                    副作用说明
                    合盖后屏幕可能还亮disablesleep 1 连 display sleep 一起禁了，背光可能不熄
                    是持久设置不恢复 disablesleep 0，Mac 会一直合盖不睡
                    发热合盖跑活（尤其 M3 Max）明显发热，别塞包里闷着

                    6合盖后 WiFi 为什么断 坑

                    「睡眠」治好了，但合盖断 WiFi 是另一个独立的物理机制

                    即使 disablesleep 1 让屏幕还亮着（没睡），合盖后 WiFi 照样可能断。原因是——MacBook 的 WiFi 天线藏在屏幕铰链里，合盖后被金属外壳遮挡，接收增益骤降。

                    • 5GHz 尤其明显：穿透力差，合盖一挡衰减最狠（连 iPhone 热点时更严重，热点信号本来就弱）。
                    • 判别方法：看当前 SSID 是不是手机热点（IP 段 172.20.10.x 就是 iPhone 热点），是的话合盖基本必断。
                    这暴露了方案的隐藏前提

                    「异地连 Mac」要求 Mac 有一条不受合盖影响的网络。靠 WiFi（尤其 iPhone 热点）上网时，合盖 = 热点断 = 整机失联，iPhone 也连不回它。根治办法：Mac 用有线网络（网线 / 雷雳网口）。

                    7完整流程 实战

                    从零到能用，以及之后每天的日常三步

                    一次性配置清单

                    侧要做的事
                    Mac装 Tailscale（brew install --cask tailscale-app）并登录
                    开远程登录（sudo systemsetup -setremotelogin on）
                    装 tmux（brew install tmux）+ 配 cafe/cafeoff 别名
                    iPhone装 Tailscale，登录同一账号，允许 VPN 授权
                    装 SSH 客户端（Termius / Blink / ShellFish）

                    日常三步

                    1. 出门前：Mac 插电，敲 cafe（合盖不睡）
                    2. 手机上：Termius 连 Mac → tmux attach -t cc（第一次是 tmux new -s cc）→ 敲 claude
                    3. 回来：cafeoff（恢复合盖睡眠）
                    两个收尾提醒

                    ① 安全：任何一次在对话里贴过 sudo 密码，装完软件就立刻改掉（系统设置 → 用户与群组 → 更改密码）。② 记不住 tmux：报嵌套警告 = 你已经在会话里了，直接敲 claude。
