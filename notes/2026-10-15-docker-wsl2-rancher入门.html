                                      Docker · WSL2 · Rancher Desktop · 入门

                                      从「容器是什么」讲到「为什么 Windows 上的 Docker 底下藏着一个 Linux 虚拟机」——把 Windows 跑 Docker 这条链路的每一层都拆开看清楚
                                      环境：Windows 11 · Rancher Desktop v1.24.0（WSL2 后端）· 实例：hindsight 容器（端口 8888 / 9999）· 信息截至 2026-10

                                      1Docker 是什么 概念

                                      先讲清「容器」这个最底层的东西，后面 WSL2、Rancher 都是为了让它能在 Windows 上跑起来

                                      1.1 一句话本质

                                      Docker 是一套「打包 + 运行」程序的技术：把程序连同它依赖的一切（库、配置、环境变量）打进一个自包含的盒子，在任何装了 Docker 的机器上都能原样跑起来。 它解决的核心痛点是「在我机器上好好的，到你机器上就跑不起来」——因为环境不一致。

                                      传统部署里，你装的软件依赖一堆系统库、特定版本的 Python、特定的环境变量。换台机器就得重来一遍，还可能因为系统版本不同失败。Docker 把这些统统装进盒子里，盒子一到，程序和它的小世界一起来了。

                                      1.2 三个核心概念：镜像 / 容器 / 仓库

                                      概念是什么类比
                                      镜像 image只读模板，打包好的程序 + 依赖，分「层」堆叠一张装系统用的 GHOST 光盘
                                      容器 container镜像跑起来的实例，在只读镜像上加一层可写层用光盘装出来的、正在运行的电脑
                                      仓库 registry存放和分发镜像的地方（如 Docker Hub、ghcr.io）App Store / 应用市场

                                      关键点：一个镜像可以跑出很多个容器，彼此隔离；容器里改的东西写在「可写层」，不污染镜像本身。所以同一镜像开 10 个容器互不影响，删掉容器镜像还在。

                                      类比

                                      镜像 = 做蛋糕的模具；容器 = 用模具烤出来的一块蛋糕。同一模具能烤无数块蛋糕，每块上想单独裱花（可写层）都不影响别的。

                                      1.3 容器 vs 虚拟机

                                      很多人第一反应是「容器不就是轻量虚拟机吗」——不是。最大的区别在内核：

                                      维度虚拟机容器
                                      内核每个 VM 带自己的完整操作系统内核共享宿主的内核，只打包应用和依赖
                                      体积GB 级（含整套系统）MB～百 MB 级
                                      启动几十秒（要启动整个系统）亚秒级（就是一个进程）
                                      隔离硬件级，最彻底进程级（namespace + cgroup），够用

                                      正因为共享内核，Linux 容器本质是 Linux 的进程——这也是为什么 Windows 上跑 Linux 容器必须先有一个 Linux 内核可用（后面 WSL2 的用武之地）。

                                      1.4 常用命令

                                      # 镜像
docker pull nginx:latest          # 从仓库拉镜像
docker images                     # 列出本地镜像

# 容器：run = create + start（一条命令建好并启动）
docker run -d --name web -p 8080:80 nginx
#        │   │         │           │
#        │   │         │           └─ 用的镜像
#        │   │         └─ 端口映射 宿主:容器
#        │   └─ 起个名字
#        └─ 后台运行（detach）

docker ps                         # 看正在跑的容器（-a 含已停的）
docker stop web && docker start web
docker logs -f web                # 跟踪日志（-f 实时刷新）
docker exec -it web bash          # 进容器里开个 shell
docker rm -f web                  # 强制删除容器
                                      两个高频参数

                                      -p 宿主:容器：把容器内的端口暴露到宿主。比如 -p 8888:8888 表示「宿主 8888 → 容器 8888」，你在 Windows 里访问 localhost:8888 才能打到容器里。

                                      -v 卷:挂载点：把数据存到容器外部，容器删了数据还在。这就是「具名卷」——不写宿主路径时 Docker 自己管理一块空间。

                                      2Rancher Desktop：Windows 上的容器引擎 工具

                                      Docker 本身是 Linux 技术，Windows 要跑它得有个「翻译层」——Rancher Desktop 就是干这个的

                                      2.1 为什么需要它

                                      Docker 引擎（dockerd）是为 Linux 写的，它依赖 Linux 内核的 namespace、cgroup 等能力。Windows 内核里没有这些，所以必须有一台 Linux 在底下撑着。Rancher Desktop 做的事就是：在你 Windows 上自动准备一台 Linux 环境、在里面跑起 Docker 引擎，再把 Windows 侧的 docker 命令接到那台 Linux 上。

                                      它的定位是「免费、开源、带图形界面的 Docker Desktop 替代品」，同时也能管 Kubernetes。引擎可选 moby（就是 Docker 引擎）或 containerd，本机用的是 moby。

                                      2.2 架构：CLI → VM → dockerd

                                      Windows 侧的 docker CLI
                                      你在 Git Bash / PowerShell 敲的 docker run，只是客户端
                                      命名管道 npipe:////./pipe/docker_engine
                                      Windows 通过这条管道把命令送进 Linux
                                      WSL2 里的 rancher-desktop 发行版
                                      一台真正的 Linux，里面跑着 dockerd（真正干活的引擎）
                                      容器
                                      镜像在这里被拉取、创建、运行

                                      看清楚这个链条：Windows 上的 docker 命令只是个「遥控器」，真正的引擎和容器都在 Linux VM 里。这也是为什么关掉 Rancher 的引擎，Windows 这边 docker ps 会直接报连接失败。

                                      2.3 配置与 CLI

                                      # 图形界面：右键托盘图标 → Dashboard / Preferences
#   启停引擎、改 CPU/内存、换容器引擎，都在这里点

# 命令行控制（rdctl = Rancher Desktop ctl）
rdctl start            # 启动 Rancher 与引擎
rdctl shutdown         # 关闭引擎（保留配置）
rdctl list-settings    # 看当前设置

# 配置文件
%LOCALAPPDATA%\rancher-desktop\settings.json

                                      自启动靠注册表 HKCU\...\Run 里的一个键，所以「开机后 Rancher 自己起来了」是它主动注册的行为，不是 Windows 内置的。

                                      3环境分层全貌 全景

                                      把前面几层摞起来看，一眼明白「你的容器到底跑在哪」

                                      3.1 自下而上五层

                                      ① Windows 11 主机
                                      你真正的物理机，跑着 Rancher 的界面和 docker CLI
                                      ② 虚拟化平台（Virtual Machine Platform / Hyper-V 组件）
                                      Windows 自带的虚拟化能力，WSL2 建在这上面
                                      ③ WSL2：轻量 Linux VM
                                      一个跑真 Linux 内核的瘦虚拟机，rancher-desktop 发行版住在这里
                                      ④ Docker 引擎 dockerd
                                      在 WSL2 发行版里常驻，负责拉镜像、建容器
                                      ⑤ 你的容器
                                      如 hindsight，最终住在这里

                                      3.2 一次 docker run 的旅程

                                      1. 你在 Windows 敲 docker run ...，docker.exe 把请求写进命名管道。
                                      2. 管道另一头，WSL2 里的 dockerd 收到请求。
                                      3. dockerd 检查本地有没有镜像，没有就去仓库拉。
                                      4. dockerd 用镜像创建容器，在 Linux 内核上分配 namespace / cgroup。
                                      5. 容器进程跑起来，-p 映射的端口通过 WSL2 的网络转发回 Windows。
                                      记住这一句

                                      你所有的容器，实际都跑在 WSL2 那个 Linux VM 里面。Windows 只是「发号施令」的地方。

                                      4WSL2 是什么 概念

                                      Windows Subsystem for Linux 第二代——它不是一个「软件」，而是 Windows 内置的一整套「在 Windows 上跑 Linux」的能力

                                      4.1 一句话本质

                                      WSL2 让你在 Windows 里直接运行一个真正的 Linux（完整 Linux 内核 + 发行版），不用装双系统、不用手动开虚拟机软件。 你能在 Windows 里敲 bash、装 apt 包、跑 Linux 程序，就像在一台 Linux 机器上一样，而且文件、命令还能和 Windows 互通。

                                      4.2 WSL1 vs WSL2

                                      维度WSL1WSL2
                                      实现方式把 Linux 系统调用翻译成 Windows 调用真的跑一个 Linux 内核（在轻量 VM 里）
                                      兼容性部分程序跑不了（如 Docker）几乎完全兼容，Docker 能跑
                                      文件性能访问 Windows 文件快访问 Linux 侧文件快（跨系统访问慢）
                                      启动秒级需启动 VM，比 WSL1 稍慢（但已很快）

                                      你用的 Docker 必须走 WSL2，因为 WSL1 提供不了真内核的那些能力。

                                      4.3 架构：服务与 VM

                                      WSL2 由几块东西组成，最容易被忽略的是「服务」和「VM」的分工：

                                      wslservice.exe · WSLService
                                      Windows 服务，开机自启（AUTO_START）——只负责「管理」，是控制平面
                                      轻量 VM（vmmem 进程）
                                      按需启动——真正跑 Linux 内核的地方，是数据平面
                                      各发行版（Ubuntu / rancher-desktop / ...）
                                      共享同一个 Linux 内核，各自隔离
                                      关键：服务开机就跑，VM 是按需的

                                      开机后 wslservice 就在了（它要管理、随时待命）；但轻量 VM 不会开机就占内存——直到你第一条 wsl 命令或 Docker 需要它时才被拉起来。这也解释了「平时看不到 vmmem 吃内存，一旦跑容器它才冒出来」。

                                      4.4 常用命令

                                      wsl -l -v                  # 列出所有发行版及状态/版本
wsl -d rancher-desktop     # 进入指定的发行版
wsl --shutdown             # 关掉整个 WSL2 子系统（所有发行版 + VM）
wsl --status               # 看默认发行版、内核版本

                                      两个配置文件别搞混：

                                      • .wslconfig（Windows 用户目录下）：管整个 WSL2 虚拟机，比如分配多少内存、多少 CPU。
                                      • /etc/wsl.conf（发行版内部）：管某一个发行版的行为，比如是否启用 systemd。

                                      5WSL2 与 Rancher 的关系 串联

                                      Rancher 不是自己造轮子，而是「借用」WSL2 这台 Linux 机来跑 Docker

                                      5.1 三个 WSL2 发行版

                                      装了 Rancher Desktop 后，wsl -l -v 会看到它建的两个发行版（加上你自己可能的 Ubuntu）：

                                      发行版作用
                                      rancher-desktop跑 Docker/K8s 引擎的「工作机」，dockerd 在里面
                                      rancher-desktop-data专门存镜像、容器数据，和引擎分离
                                      （你的）Ubuntu 等你自己装来日常开发用的，和 Rancher 共用同一个 VM

                                      它们共享同一个 Linux 内核（WSL2 的设计），但 rootfs、进程、网络各自隔离——所以 Rancher 的引擎和你自己的 Ubuntu 互不干扰。

                                      5.2 Windows 如何连上 VM 里的 dockerd

                                      连法就是那条命名管道：

                                      # Windows 侧 docker CLI 连接的目标
npipe:////./pipe/docker_engine

                                      Rancher 在 Windows 侧把这个管道「转发」到 rancher-desktop 发行版里的 dockerd。于是你敲 docker ps，请求走管道 → 进 Linux → dockerd 执行 → 结果原路返回。CLI 在 Windows，引擎在 Linux，两者靠管道握手。

                                      一句话总结这层关系

                                      WSL2 提供「一台现成的 Linux 机」，Rancher 在这台机上「装了 Docker 引擎 + 架了根电话线（命名管道）通到 Windows」，你在 Windows 拿电话下单，Linux 那头的引擎真正干活。

                                      6关键辨析：WSL2 是「Windows 的服务」吗 澄清

                                      这是最容易形成的错误心智模型，值得单独掰清楚

                                      6.1 这个说法为什么不准确

                                      你最初的直觉是：「WSL2 的本质其实是 Windows 操作系统的一个服务。」 这句话对了一半，但整体是错的——它只看到了「管家」，丢掉了「真正干活的人」。

                                      WSL2 其实是好几样东西的组合，至少包括：

                                      • 一个 Windows 服务 wslservice.exe——负责管理、协调，是「管家」；
                                      • 一个真正的 Linux 内核——跑在轻量 VM 里，才是真正执行你命令的「干活的」；
                                      • 虚拟化平台（Virtual Machine Platform / Hyper-V 相关组件）——提供跑那个 VM 的底座；
                                      • 各发行版的用户态（Ubuntu、rancher-desktop 的文件系统、apt 等）。

                                      把 WSL2 等同于「一个服务」，就像把一家公司等同于它的前台——前台确实是公司的一部分，也确实是「开机就在」的那个，但真正产出价值的是后面的团队。

                                      6.2 控制平面 vs 数据平面

                                      你熟悉 IC，用控制平面 / 数据平面来对齐最贴切：

                                      控制平面（管理）数据平面（干活）
                                      WSL2 里对应wslservice.exe 服务轻量 VM 里的 Linux 内核 + 各发行版
                                      IC 里对应管理单元：配置寄存器、握手、调度数据通路：真正搬数据的那条链
                                      是否开机就在是（AUTO_START）否（按需拉起）
                                      类比

                                      餐厅：前台/领班 = 服务，负责接待、安排座位、把单子传下去；真正做饭的厨房 = VM 里的 Linux 内核。说「这家餐厅就是前台」显然漏掉了整个厨房。

                                      芯片：把「一块 SoC」等同于「它的一组配置寄存器」——寄存器确实开机就有、也确实是 SoC 的一部分，但 SoC 的主体是数据通路。服务之于 WSL2，就相当于配置寄存器之于 SoC。

                                      6.3 修正后的心智模型

                                      把最初的话修正成这样，就准确了：

                                      修正版

                                      WSL2 是 Windows 内置的一整套「在 Windows 上跑真 Linux」的能力，由 一个常驻服务（控制平面） + 一个按需启动的轻量 Linux VM（数据平面） + 一组发行版 组成。那个服务负责管理和拉起 VM；真正执行命令、承载容器的，是 VM 里的 Linux 内核。

                                      而 Rancher 与它的关系也顺势清晰了：Rancher 是「调用方」——它通过 WSL2 的服务，拉起（或接入）那台轻量 VM，在里面的 rancher-desktop 发行版上跑起 dockerd；Windows 侧的 docker CLI 则通过命名管道遥控这个 dockerd。服务在管、VM 在算、Rancher 在调度、CLI 在下单——四者各司其职，谁都不是谁的「本质」。
