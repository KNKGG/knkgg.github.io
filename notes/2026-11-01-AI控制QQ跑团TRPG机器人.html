                AI 控制 QQ 跑团（TRPG）机器人

                NapCat + DiceFrame + 本地 Qwen：从选型、部署、踩坑到开团，一条完整记录
                组件：NapCat(Docker) · DiceFrame · llama.cpp + Qwen3.5-35B-A3B · 信息截至 2026-11-01

                1方案概览与架构 原理

                让 AI 当 GM/KP，玩家在 QQ 群里自然语言跑团；GM（你）在 WebUI 建团管理

                整体是三层拼装：QQ 消息经协议端转成标准接口，喂给跑团引擎，引擎里的 LLM 负责剧情叙述、检定判定和掷骰。分工如下：

                协议层 · NapCat（Docker 跑 Linux 版）
                把 QQ 账号变成 OneBot v11 接口，消息收发统一走 ws://127.0.0.1:3001

                ↓ OneBot WebSocket（正向，array 消息段）

                框架层 · DiceFrame（源码部署）
                自托管 AI 跑团引擎，内置 qq-napcat 插件连 NapCat；管理角色卡/世界书/骰子/状态

                ↓ OpenAI 兼容 Chat Completions

                AI 层 · Qwen3.5-35B-A3B（本地）
                llama.cpp + Metal，llama-server 起在 127.0.0.1:8080/v1，当 GM 主模型

                角色分工

                角色在哪操作干什么
                GM（你）DiceFrame WebUI建团、建卡、绑定群、推进回合
                玩家QQ 群@Bot 提交行动、认领角色、提问
                AI（本地 Qwen）引擎内部剧情叙述、检定判定、掷骰结算

                2技术选型 选型

                三个关键决策：协议端选 NapCat、引擎选 DiceFrame、AI 用本地 Qwen

                协议端：NapCat（唯一活跃 + macOS 可跑）

                方案状态结论
                NapCatQQ12k star，日更首选，功能全、活跃
                Lagrange.Core活跃，但 OneBot 前端已归档Core 还在，前端 404，不可用
                LLOneBot改名 LuckyLilliaBot，Windows 为主macOS 支持弱，弃

                引擎：DiceFrame（唯一全满足）

                选它的关键：唯一内置 QQ/NapCat 接入 + COC 7e / D&D 5e / 自定义规则 + 本地 LLM 支持 + 官方中文 UI。对比：

                • NarrativeEngine（109 star）：纯本地 AI DM，但无 QQ 接入，偏单人 WebUI。
                • Loreweaver（67 star）：D&D/CoC 双规则，但走 P2P 联机（Iroh），无 QQ。

                AI：本地 Qwen（去审查版）

                M3 Max 36GB 跑 Qwen3.5-35B-A3B（MoE）Derestricted 去审查版——跑团（尤其 COC 恐怖/悬疑）正需要不被安全审查卡住。llama.cpp 的 llama-server 天然提供 OpenAI 兼容端点，DiceFrame 直接接，无需 Ollama。

                为什么是「本地 LLM」而不是 API

                跑团是长上下文剧情对话，本地 Qwen 零 token 成本、无内容审查、隐私全在自己机器；DeepSeek 可作回退。35B-A3B 是 MoE，Metal 上跑流畅。

                3部署记录 实操

                三个组件分别在 macOS（M3 Max）上怎么装起来的

                ① DiceFrame（源码部署）

                git clone ssh://git@github.com/diceframe/diceframe.git ~/diceframe
cd ~/diceframe/frontend-v2 && npm ci --registry=https://registry.npmmirror.com && npm run build
cd ~/diceframe && pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
python3 web_server.py   # WebUI 起在 18000

                LLM 配置直接写 data/config.json：ai_providers 里加一条本地 provider，llm_provider_ref 指向它，model 填 gguf 路径（本地 provider 空 key 即可）。

                ② NapCat（Docker 跑 Linux 版）

                ~/napcat-docker/compose.yaml：

                services:
  napcat:
    image: mlikiowa/napcat-docker:latest
    restart: unless-stopped
    environment:
      MODE: ws          # 正向 WebSocket，监听 3001
      WEBUI_TOKEN: <你的 token>
    ports:
      - "127.0.0.1:6099:6099"   # NapCat WebUI
      - "127.0.0.1:3001:3001"   # OneBot WebSocket
    volumes:
      - ./data/qq:/app/.config/QQ       # QQ 登录态持久化
      - ./data/config:/app/napcat/config
      - ./data/plugins:/app/napcat/plugins

                镜像内置匹配的 Linux QQ + NapCat，自洽，扫码登录一次后登录态存卷里，重启不用重扫。

                ③ 本地 LLM（llama.cpp）

                ~/llama.cpp/build/bin/llama-server \
  -m ~/models/Qwen3.5-35B-A3B-Q4_K_M.gguf \
  -ngl 99 -c 32768 -fa on \
  --cache-type-k q4_0 --cache-type-v q4_0 \
  --reasoning off --host 127.0.0.1 --port 8080

                DiceFrame 的 provider base_url 填 http://127.0.0.1:8080/v1（客户端自动拼 /chat/completions）。

                4踩坑速查 踩坑

                这一套从头搭下来踩的坑，按出现顺序排

                坑症状解法
                QQ 版本死结QCE macOS 版（NapCat 4.18.28）报 PacketBackend 不支持 6.9.79，只认 QQ 6.9.82(40990)，而它已被腾讯下架换 Docker 跑 NapCat Linux，镜像内置匹配 QQ，绕开版本问题
                Docker Hub 被墙registry-1.docker.io 拉镜像超时配镜像加速器 docker.m.daocloud.io
                插件 macOS 兼容 bugqq-napcat 插件连上 NapCat 后 2 秒自杀，日志 检测到主进程已退出_pid_exists() 依赖 Linux /proc，macOS 上误判；改 main.py 加 os.kill(pid,0) 回退
                aiohttp 太旧DiceFrame 启动报 web.RequestKey 不存在anaconda 里 aiohttp 3.9.3 缺新 API，升到 3.14.5
                npm 官方源慢npm ci 卡住（CPU 0.4%，等网络）lock 里硬编码 npmjs.org，加 --registry=https://registry.npmmirror.com
                brew 装 Docker 卡 sudobrew install --cask docker 在链接二进制时卡 sudo 密码，回滚手动挂 dmg 复制 Docker.app 到 /Applications
                docker 凭据助手缺失拉镜像报 docker-credential-desktop not found软链接 /Applications/Docker.app/Contents/Resources/bin/docker* 到 /opt/homebrew/bin
                一句话总结

                这套方案的「坑」集中在macOS 不是 NapCat 的一等公民：macOS 原生版有版本死结，于是退到 Docker 跑 Linux；而插件、aiohttp 这些又暴露了「源码部署在 macOS 上」的小兼容问题。跑通之后都是一次性成本，脚本化了就不会再踩。

                5使用指南 使用

                第一次开团 → 搬到 QQ 群 → 平时怎么玩

                第一次开团（GM 在 WebUI）

                1. 浏览器开 http://127.0.0.1:18000，输访问密码
                2. Overview → Create Adventure，选规则（CoC 7e / D&D 5e / 自定义）、语言中文
                3. Characters 建角色卡（可手填，也可 AI 辅助生成）
                4. Play 页面直接开跑（单人 / 网页玩家）

                搬到 QQ 群

                1. GM 在 WebUI 房主页复制 Bot 绑定命令（含 game_key + 一次性凭证）
                2. 发到群里：@Bot 绑定 <game_key> <凭证>
                3. 玩家 @Bot 加入 角色名 认领角色

                QQ 群核心命令

                命令作用
                @Bot 帮助查看当前群可用指令
                @Bot 加入 角色名认领已有角色
                @Bot <自然语言行动>核心：提交行动，如「@Bot 我推开那扇旧木门」
                @Bot 询问 <问题>桌外问 KP，不消耗行动、不推进剧情
                @Bot 状态 / @Bot 前情 / @Bot 地图看 HP/物品 / 前情提要 / 场景与世界书
                @Bot 新建角色 / @Bot AI车卡群里引导建卡
                @Bot 推进 / @Bot 下一轮GM（或授权账号）强制推进回合
                跑团循环（自动的）

                所有在场玩家提交行动后自动推进（GM 也可 @Bot 推进）→ AI 判定是否需要检定 → 需要就服务端自动掷一次骰、直接展示结果 → Qwen 继续叙事进入下一轮。玩家只描述「想干什么」，不用记规则。

                单人也能玩

                不接 QQ 也行——直接在 WebUI 的 Play 页面自己输入自然语言行动，AI 当 GM 陪你跑，是最快验证「本地 Qwen 当 GM 效果」的方式。

                6启动 / 停止脚本 配置

                两个脚本放在 ~/，幂等，重复跑不出错

                启动 ~/start-trpg.sh

                ~/start-trpg.sh

                三步：① Docker Desktop + NapCat 容器（等 engine 就绪）→ ② llama-server（8080 没监听才启动）→ ③ DiceFrame（1800 没监听才启动）。最后打印 WebUI 地址和访问密码。

                停止 ~/stop-trpg.sh

                ~/stop-trpg.sh

                四步：① DiceFrame + QQ 插件 → ② llama-server → ③ NapCat 容器 → ④ 退出 Docker Desktop（释放内存，llama 21GB + Docker 2GB+ 都吃在 36GB 上）。

                下次怎么用

                开机后 ~/start-trpg.sh 一条命令全起，收工 ~/stop-trpg.sh 一条命令全停。NapCat 登录态在卷里，通常不用重扫；真掉登录就 docker logs napcat 取新二维码。
